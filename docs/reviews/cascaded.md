### 1.2 Per-chunk pipeline inside the fused kernels

**Compression** (`do_cascaded_compression_kernel`, `CascadedKernels.hiph:761-1058`), per partition (one block):

1. `num_chunks = ceil(num_input_elements / chunk_num_elements)` with `chunk_num_elements = 4096 / sizeof(T)` (777, 878).
2. Per chunk: reserve `chunk_metadata_size` uint32s in the output (886), load the chunk global → LDS `shared_element_buffer_0` with a `threadIdx.x += blockDim.x` scalar loop (896-902), `__syncthreads`.
3. Layer loop `for layer_idx < max(num_RLEs, num_deltas)` (910-980): if RLE remains → `block_rle_compress` (in: `shared_input_buffer`, out: values → `shared_output_buffer`, counts → `shared_count_buffer`, tmp indices → `shared_tmp_buffer`, `num_outputs` in LDS) then `block_write<run_type=uint16_t>` of the counts to global, optionally bit-packed via `block_bitpack` into `shared_tmp_buffer` (925-936); swap in/out buffers; then if delta remains → `block_delta_compress` (out[i] = in[i+1]-in[i]) and thread 0 writes `in[0]` to the LDS `delta_header` (955-977); swap; `__syncthreads` (979). Note: RLE and Delta share the ping-pong pair `shared_element_storage_0/1`.
4. Final `block_write<data_type>` of the surviving value array (986-997), bit-packed using `shared_output_buffer` as the packing scratch.
5. Thread 0 flushes the 64-B-max chunk metadata staged in LDS to the reserved header slot (1004-1014).
6. If any `block_write` reports out-of-bound → `use_compression=false`, fall back to raw copy (1020-1029), header fields zeroed (1044-1053).
7. Thread 0 writes the 8-B partition header (1032-1056).

**Decompression** (`cascaded_decompression_fcn`, `CascadedKernels.hiph:1106-1435`), per partition (one block):

1. LDS carve-up from the caller-provided `shmem` (1135-1179): 64 B chunk metadata | `shared_element_storage_0` | `_1` | `count_array` | `temp_count_array` | `rle_offsets` (32 B).
2. Per chunk (`while chunk_ptr < partition_end_ptr`, 1268-1414): load chunk metadata (1279-1283), thread 0 computes `rle_offsets[]` serially (1291-1306), `block_read` the final array (bit-unpack into `shared_input_buffer` via `block_bitunpack`, 1315-1326).
3. Layer loop in reverse (1332-1391): delta → `block_delta_decompress` (BlockScan per 128-element round, 344-377) ; RLE → `block_read` the count array (bit-unpack into `count_array` using `temp_count_array`), then `block_rle_decompress` (BlockScan per 128-run round + per-thread serial expansion, 260-305).
4. Copy the chunk from LDS to global, scalar `sizeof(T)` stores (1404-1407); advance `chunk_ptr` by `chunk_metadata[0]` (1412-1413).

Type dispatch: host side via `type_macros.h` for compression; device side by reading the header byte for
decompression (all four width variants launched). Signedness is erased inside the kernel (decompression
always runs `uintN_t`), which is correct because RLE/delta/bitpack are defined on the raw bit pattern
with the `std::make_signed_t` trick only in `get_for_bitwidth` (405) — note that signedness does affect
the FOR/bitwidth computed at compression time, which is why the compressor is instantiated on the real type.

### 1.3 On-the-wire format (as implemented)

- Partition header, 8 B (`CascadedKernels.hiph:1033-1055`): byte0 `num_RLEs`, byte1 `num_deltas`, byte2 `use_bp`, byte3 `arctoType_t`, bytes 4-7 `uint32` uncompressed bytes. Chunks start at the first `data_type`-aligned address after the header (873-876).
- Chunk metadata (`get_chunk_metadata_size`, 101-106; comment at 1127-1134): `uint32` compressed chunk size | `uint32 × (num_RLEs+1)` byte sizes of each RLE count array and of the final array | `data_type × num_deltas` first elements of each delta layer; padded so the whole thing is a multiple of 4 and of `sizeof(T)`; asserted ≤ 64 B (821-826).
- Arrays after the metadata: RLE count arrays in layer order, each starting 4-B aligned; the final array starts `max(4,sizeof(T))`-aligned (1291-1304, 983-984).
- Bit-packed array layout (`block_bitpack`, 498-521): `data_type` frame-of-reference | `uint32` `(bitwidth<<16)|num_elements` | 4-B-aligned (and `data_type`-aligned) packed `uint32` words, little-endian bit order within a word, elements never split across anything but consecutive words.
- Fallback: header with zeros + raw copy at the first `data_type`-aligned offset after 8 B (1023-1028, 1240-1246).
- Limits: `chunk_num_elements < 65536` (uint16 runs and 16-bit element count) (783); `num_RLEs <= 7` on decode (1209); partition ≤ 4 GiB (844).

### 1.4 Shared-memory (LDS) layout and sizes (chunk = 4096 B)

Compression, static `__shared__` inside `do_cascaded_compression_kernel` (789-837) + collectives' `TempStorage`:

| T | elem storage ×2 (795-804) | count buf (806-810) | tmp buf (815-816) | meta+num_outputs | ≈ total |
|---|---|---|---|---|---|
| u8  | 2×4104 | 8192 | 8200 | 72 | **≈24.7 KB** |
| u16 | 2×4104 | 4096 | 4104 | 72 | ≈16.5 KB |
| u32 | 2×4104 | 2048 | 2056 | 72 | ≈12.4 KB |
| u64 | 2×4112 | 1024 | 1032 | 72 | ≈10.4 KB |

plus hipcub `BlockScan<size_t,128>::TempStorage` (158) and two `BlockReduce<_,128>::TempStorage` instantiations
(412; one for `data_type`, one for `run_type=uint16_t` since `block_write<run_type>` also bit-packs) — each small
(tens to a few hundred bytes with rocprim's warp-shuffle based implementations) but non-aliasable static LDS.

Decompression `compute_smem_size<4096,w,sw>()` (1069-1080): u8 **24 688 B**, u16 16 496 B, u32 12 400 B, u64 10 368 B,
plus `BlockScan<uint16_t,128>` (274) and `BlockScan<data_type,128>` (351) temp storage. HLIF uses the same numbers
(`CascadedHlifKernels.hip:139-143`).

Occupancy consequence (LDS-bound, 128-thread blocks): on CDNA2/CDNA3 (64 KB LDS per CU, wave64 ⇒ a block is 2 waves)
that is ≈2/3/5/6 blocks per CU for u8/u16/u32/u64 ⇒ **1–3 waves per SIMD** out of 8. On RDNA3 (gfx1100, wave32 ⇒ 4 waves per block,
128 KB LDS per WGP) ≈5–12 blocks per WGP ⇒ 5–12 waves per SIMD out of 16. The kernels are latency/barrier-bound, so this
low occupancy on CDNA is the single most important structural fact for the whole review.

## 3. NVIDIA-isms and AMD pitfalls found (file:line)

1. **128-thread blocks tuned for warp32, with 10–25 KB of static LDS ⇒ LDS-bound occupancy of 1–3 waves/SIMD on CDNA.**
   `src/CascadedKernels.hiph:94-95` (`cascaded_compress/decompress_threadblock_size = 128`), LDS sizes in `:795-823`, `:1069-1080`, `CascadedBatch.hip:174-241`.
   On NVIDIA a 128-thread block is 4 warps and 48 KB smem/SM with 12–25 KB per block still gives 2–4 blocks ⇒ 8–16 warps/SM. On CDNA (64 KB LDS/CU) a 128-thread block is only 2 wave64s; at 24.7 KB (u8) two blocks fit ⇒ 4 waves per CU ⇒ 1 wave per SIMD. Every `__syncthreads`/LDS round trip is then fully exposed.

2. **No `__launch_bounds__` on any Cascaded kernel** (`CascadedBatch.hip:102, 156, 262`; `hlif_shared.hiph:232-236, 391-401`). hip-clang then assumes a flat work-group size up to 1024 and budgets VGPRs accordingly; and the compiler gets no occupancy target. The macros that exist in `src/amd_optimizations.h:103-113` are not used on this path, and their comment (`:98` "min_blocks_per_cu") mis-describes HIP semantics: in HIP-Clang the second argument of `__launch_bounds__` is **minimum waves per execution unit (SIMD)**, not blocks per CU. E.g. `AMD_LAUNCH_BOUNDS_HIGH_OCC = (256, 8)` caps VGPRs at 64 on CDNA, `(1024,4)` at 128. Used on the legacy kernels only (`BitPackGPU.hip:225,286`, `DeltaGPU.hip:82`, `RunLengthEncodeGPU.hip:176,231,363`) where e.g. a 128-thread `rleReduceKernel` carries `(1024,4)`.

3. **hipcub `BlockScan` left on the CUB default `BLOCK_SCAN_RAKING`** at `CascadedKernels.hiph:157, 273, 350` and `RunLengthEncodeGPU.hip:286`. In hipcub this maps to `rocprim::block_scan_algorithm::reduce_then_scan`; rocprim's own default and usually faster choice on AMD is `using_warp_scan` (= hipcub `BLOCK_SCAN_WARP_SCANS`), which keeps the per-wave scan in DPP/`ds_swizzle`/`v_permlane` and touches LDS once for the wave prefixes. `BlockReduce` is on `BLOCK_REDUCE_WARP_REDUCTIONS` (→ `using_warp_reduce`), which is fine. (Mapping recalled from hipcub `hipcub/rocprim/block/block_scan.hpp`; verify against the installed hipcub version — no ROCm headers on this machine.)

4. **Per-128-element round structure with a collective + barrier per round** — sized for 4 warps, it degenerates on AMD where the same number of barriers is paid by only 2 waves and the kernel cannot overlap anything:
   - `get_for_bitwidth` (`CascadedKernels.hiph:394-471`): for every 128 elements, two `BlockReduce` + two `__syncthreads` (421-425, 438-442). For a u8 chunk (4096 elements) that is 64 block reductions and 64 barriers just to find min/max; for u32 (1024) it is 16+16. It is called for every bit-packed array: each RLE count array and the final values (925-936, 986-997).
   - `block_delta_decompress` (343-377): one `BlockScan` + barrier per 128 elements (u8: 32 rounds).
   - `block_rle_decompress` (255-305): one `BlockScan` + barrier per 128 runs.
   hipcub/rocprim collectives have `ITEMS_PER_THREAD` overloads that would do the same work in 1/8th the rounds — execution only.

5. **LDS bank conflicts in RLE compress**: `block_rle_compress` assigns `num_inputs_per_thread = chunk_num_elements/128` **consecutive** elements per thread (`CascadedKernels.hiph:160-161, 167-183, 196-217`). For every `T` the per-lane stride is 4096/128 = **32 B = 8 dwords**, so within any 32-lane LDS service group only 4 of 32 banks are touched ⇒ ~8-way conflicts on every `input_buffer[...]` read in Steps 1 and 3 (two full passes over the chunk per RLE layer). Same pattern in the legacy `rleInitKernel/rleReduceKernel` (`RunLengthEncodeGPU.hip:208-215, 273-279, 305-315`, stride 8 elements). NVIDIA suffers the same 8-way conflict, but AMD has half the LDS bandwidth per wave-instruction relative to VALU, and wave64 means 64 lanes queue on those banks.

6. **Serial, divergent RLE expansion**: `block_rle_decompress` lets each thread write its own run `current_count` times (`CascadedKernels.hiph:290-296`). One run of 4096 u8 elements with 127 one-element runs ⇒ one lane does 4096 LDS stores while 63 lanes idle; on wave64 the exposed imbalance is 2× worse than on warp32.

7. **Scalar per-element global traffic**: chunk load `T` per lane (`CascadedKernels.hiph:896-902`: for u8 that is `global_load_ubyte`, 64 B per wave-instruction, 32 iterations per chunk), final decompressed store `T` per lane (1404-1407), fallback/raw copies (1025-1028, 1242-1246), and `uint32` per lane in `block_read/block_write` (722-725, 673-677). No `dwordx4` anywhere. AMD's memory pipeline wants 16 B per lane (`global_load_dwordx4`) to reach bandwidth; with 1–3 waves/SIMD there is also too little memory-level parallelism to hide latency with narrow loads.

8. **HLIF scratch→output copy uses byte stores**: `hlif_shared.hiph:138-148` loads `char4` then issues 4 `global_store_byte` per lane. For Cascaded all `comp_chunk_sizes` are multiples of 4 (`CascadedKernels.hiph:1041-1043` ⇒ `current_output_ptr` is 4-aligned; fallback 1050-1052 rounds to 4) so offsets are multiples of 4 and a dword path would always be taken.

9. **Four decompression launches per call**, three of which are no-ops (`CascadedBatch.hip:387-429`), each still grid = batch_size and each doing one global load of `compressed_data[0]` per block. Launch latency on ROCm (~5–15 µs) is higher than on CUDA; for small batches this is measurable. (Also a latent assumption that all partitions share the type of partition 0 — correctness, not perf.)

10. **64-bit where 32-bit suffices**: `BlockScan<size_type=size_t,128>` in RLE compress (`CascadedKernels.hiph:157,189-190`) scans values ≤ 4096; `num_outputs`, `out_bytes`, `num_elements_current_chunk` are `size_t` (837-838, 890-892). On AMD every 64-bit add/compare is 2 VALU ops and 64-bit LDS traffic for the scan; 32-bit is enough inside a 4096-B chunk. Format unaffected (only the stored `uint32` sizes are on the wire).

11. **`blockDim.x` vs template constant mixed**: `CascadedKernels.hiph:324, 585, 675, 898, 1026, 1244` use `blockDim.x`; others use `threadblock_size`. Using the constant lets the compiler fold trip counts/unroll; `blockDim.x` comes from the dispatch packet (SGPR load) and blocks unrolling. Minor.

12. **Runtime integer divisions by `bitwidth`** inside the per-word bit-pack loop (`CascadedKernels.hiph:531-532`, 2 per output word) — AMD has no integer divide instruction (~20–40 VALU ops each). Minor, but it sits in the inner loop.

13. **Thread-0 serial work at chunk granularity**: metadata flush (`CascadedKernels.hiph:1004-1014`) and `rle_offsets` prefix (1291-1306). Small (≤16 words) but each is a serialization point between barriers.

14. **Wave32 build (gfx1100)**: `USE_WARPSIZE_32` only changes `arcto::warpsize`/`amd::WAVEFRONT_SIZE` (`CMakeLists.txt:128-132`, `src/arcto_device_types.h:28-44`, `amd_optimizations.h:46-65`); the Cascaded path uses neither, and rocprim picks the device wave size itself, so nothing here is wave-size-incorrect. But the 128-thread/LDS sizing was never revisited for 4-wave blocks either.

15. **`assert()` in device code** (`CascadedKernels.hiph:783, 826, 844, 1209`): compiled out only if `NDEBUG` is defined. `CMakeLists.txt:162-169` forces `Release` when unset, and CMake's default `CMAKE_HIP_FLAGS_RELEASE` is `-O3 -DNDEBUG`, so normally fine; a `RelWithDebInfo` build would keep them (device `assert` on AMD is a trap + printf path and disables some optimizations).

16. **CUDA-shim portability points to keep in mind for any fix**: `include/cuda_shim/hip/hip_runtime.h:26-72` maps only runtime API names; device intrinsics must stay in the common HIP/CUDA subset (`__shfl_*` without `_sync` is deprecated/removed on CUDA ≥ 12 — `amd_optimizations.h:248-256` already routes through `wave_shfl_down` for that reason); `__builtin_nontemporal_*`, `__builtin_amdgcn_*`, `__attribute__((amdgpu_waves_per_eu))` need `#if defined(__HIP_PLATFORM_AMD__)` guards.
